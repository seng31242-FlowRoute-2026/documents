### Functional Requirements: Intake and Routing Modules

| ID        | Title                   | Description                                                                                                                                             | Priority      | Source                    | Verification                                              |
| :-------- | :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------ | :------------------------ | :-------------------------------------------------------- |
| **FR-01** | Video File Upload       | Raw video files shall be securely uploaded to the system via the Client Intake Portal.                                                                  | P1 - Blocker  | UC-01 / Client Validation | Test Case TC-FR-01 (integration test; see SDS Appendix A) |
| **FR-02** | Upload Constraints      | Uploaded video files shall be validated against a maximum file size constraint of 50 Megabytes (50MB) prior to system acceptance.                       | P1 - Blocker  | UC-01 / AC3               | Test Case TC-FR-02 (unit test; see SDS Appendix A)        |
| **FR-03** | Intake Confirmation     | A submission confirmation shall be displayed to the client upon the successful upload and validation of the video file.                                 | P3 - Major    | UC-01                     | Test Case TC-FR-03 (e2e test; see SDS Appendix A)         |
| **FR-04** | Routing Trigger         | The automated routing algorithm shall be triggered immediately upon the successful completion of a video file upload.                                   | P1 - Blocker  | UC-02 / AC3               | Test Case TC-FR-04 (integration test; see SDS Appendix A) |
| **FR-05** | Capacity Retrieval      | The active task queue depth and real-time capacity of all editing pods shall be retrieved by the routing engine prior to assignment.                    | P1 - Blocker  | UC-02                     | Test Case TC-FR-05 (integration test; see SDS Appendix A) |
| **FR-06** | Automated Assignment    | The newly uploaded video task shall be automatically assigned to the editing pod currently holding the lowest task count.                               | P1 - Blocker  | UC-02                     | Test Case TC-FR-06 (unit test; see SDS Appendix A)        |
| **FR-07** | Assignment Notification | Assignment notifications shall be dispatched to the designated pod lead and Product Owner once a task is successfully routed to a pod.                  | P2 - Critical | UC-02 / AC3               | Test Case TC-FR-07 (integration test; see SDS Appendix A) |
| **FR-08** | Manual Override         | The automated routing process shall be manually overridden by the Product Owner in the event of an active capacity bottleneck or structural deadlock.   | P1 - Blocker  | UC-03 / Risk Mitigation   | Test Case TC-FR-08 (e2e test; see SDS Appendix A)         |
| **FR-09** | Task Reassignment       | Tasks shall be manually re-assignable by the Product Owner to an alternative pod to resolve unexpected workload imbalances or emergency offline states. | P2 - Critical | UC-03 / Risk Mitigation   | Test Case TC-FR-09 (integration test; see SDS Appendix A) |
| **FR-10** | Routing Audit Logging   | All automated and manual task assignment events shall be logged within the system to maintain a verifiable history of workload distribution.            | P3 - Major    | UC-02                     | Test Case TC-FR-10 (unit test; see SDS Appendix A)        |
